# 当前版 DOTA2 技能编辑器

这是独立于历史档案馆的 Windows 桌面工具。制作与初始实测基线为 **7.41f / build 6944 / SourceRevision 11085649**，客户端构建日期为 2026-10-05。**0.1.2 起不再按游戏版本、build 或 SourceRevision 拒绝准备、启动及连接**；界面同时显示制作基线和实际客户端构建，差异只作提示。普通本地比赛、原生英雄试玩及其他本机监听服务器中的作弊环境使用本机真实技能定义和服务端 Lua；远端服务器只有作弊开关并不满足条件。

## 使用

1. 打开 `Dota Current Skill Editor.exe`，选择含 `game` 子目录的当前 DOTA2 客户端，查看实际构建并点击“一键准备”。构建与制作基线不同仍可继续。
2. 从工具启动普通本地机器人比赛，或启动主菜单后自行进入英雄试玩/本地房间。选定英雄；本地房间需启用作弊。
3. 选定英雄后等待桌面技能面板自动连接，搜索中文名、英文名、内部名或来源英雄。添加后可调整等级和移除本工具新增的实例；普通本地比赛无需手动输入加载命令。
4. 退出游戏后点击“恢复工具文件”，删除仍与安装指纹一致的工具文件。其他来源的文件或外部修改会保留。

桌面面板必须使用由本工具启动的游戏控制通道。已手动启动的客户端需先退出，再从工具启动；不接管外部进程。工具启动提供 F8 备用控制台键，手动启动的游戏使用自己设置的控制台键。

关闭桌面工具不会关闭游戏或自动恢复安装文件。工具文件会保持安装状态；重新打开同一工具可重新连接仍符合归属检查的游戏。退出游戏后再显式恢复。

官方英雄试玩与符合环境检查的本地游廊可选择桌面或游戏内 Panorama 面板。在桌面技能区点击“打开游戏内面板”，或“关闭游戏内面板 / 使用桌面”；切换保留已添加技能，资源预载期间暂不可切换。游戏内面板的关闭按钮采用同一切换操作，不取消桌面正在预载的添加。

游廊使用引擎当前挂载的 `addoninfo.txt` 核对可玩标记与精确地图名称，还需有效的自定义游戏实体和动态 HUD 接口。游廊默认使用桌面，只有显式打开才请求游戏内面板；官方英雄试玩仍默认打开。面板状态区分“已请求，等待游戏内确认”和实际本机玩家握手完成的“已显示”。这组检查并不保证每张游廊的 HUD 都兼容，未完成握手时可继续使用桌面。

普通比赛不调用 `DynamicHud_Create`：本机构建在普通 `dota` 上创建完整或最小面板都会于客户端产生访问违规。普通比赛仅使用桌面，修改继续在该本地服务器执行。自定义地图也可能叫 `dota`，因此地图名称本身不作为普通比赛或游廊的判据。

控制台可使用以下固定命令；桌面连接仍要求由本工具启动游戏：

```text
sv_cheats 1
script_reload_code current_skill_editor_v1.lua
current_skill_panel open
current_skill_panel close
```

重复加载时的 `CURRENT_SKILL_REUSE`、`LOADED ... reused` 表示复用当前 Lua 实例并保留新增技能；`PANEL closed` 表示重置自己的面板握手，`skipped_non_demo` 是旧版跳过非试玩界面的提示，不代表技能服务失效。工具源码升级后需重启客户端载入新的 Lua 实例；重复执行 reload 不会替换正在使用的旧实例。新版手动关闭后会保持关闭，重复加载不会强制重开。

## 能力与边界

- 编辑目录来自本机构建的 `npc_abilities`、`items` 与合并后的英雄 `AbilityDefinitions`；名字从本机 UTF-8 本地化包提取，并由真实定义 ID 筛选。
- 支持搜索、分页、常规与高级分类、添加、等级调整、移除工具新增技能。原技能与天赋只读；不支持清空或随意改写原英雄。
- 先天、命石、调用器/复制类技能、隐藏项和物品技能有额外依赖。允许尝试并不代表每项都兼容跨英雄使用。
- 守护依据本地主机 pawn→controller→当前真实英雄关系，拒绝远端控制、他人英雄、幻象与分身。机器人不构成单人限制；跨机多人效果尚需另行验收。
- 新增状态只属于当前 Lua VM/英雄实例。退出地图、换英雄或重开游戏后需重新添加。
- 使用 `-dev -insecure` 的本地测试客户端。正常在线比赛请退出后从 Steam 常规入口启动。

## 原创文件与控制通道

发行资源仅四项原创内容：Lua、编译后的 JS、CSS 和 XML。安装另生成两个本机文件：技能名字索引与随机会话能力凭据。六个精确路径均由安装清单管理；先持久化创建意图，再独占创建；相同的已有内容不归工具所有，不同内容拒绝覆盖。没有 Valve 客户端、DLL、VPK、地图、原技能实现或名称文本随发行包分发。

控制通道只连接 `127.0.0.1`，每次发命令前后核验 PID、可执行路径、创建时间和监听端口归属。原生控制监听可能绑定所有网卡，使用每次启动产生的强随机密码；凭据在工具旁的 `data` 目录中以 Windows DPAPI 密封，绑定当前 Windows 用户。技能操作还需单独随机能力凭据，固定动作与数据参数不能执行任意 Lua 文本。服务器的最终状态回包用于更新面板，不以按钮点击或文件安装成功代替实际修改成功。

工具界面与源码完全离线，无遥测、云端认证、运行时 CDN 或更新服务。当前官方客户端与 Steam 的联网行为由游戏自身决定。

## 构建与验证

作者源位于 `src/current-skill-editor` 与 `tools/current-ability`。不要修改 `tools/legacy-ability` 或历史档案馆的 7.22 入口来适配当前版。

```powershell
node scripts/build-current-skill-editor.cjs "当前客户端目录"
npm start
npm run pack
```

编译使用玩家安装目录的同构建 Resource Compiler，原工具和资源不进入发行包。现代 VJS 资源版本为 4，VXML/V CSS 为 3。编译临时目录与对应原创 `gameinfo.gi` 位于忽略的 `local`。

Steam 更新后可继续尝试原工具；是否兼容由实际加载、服务器回包和面板握手决定，不由版本编号决定。六个工具文件的内容和归属仍逐项核验；恢复不依赖原游戏版本。准备时的技能与名字索引读取本机游戏，更新后如需刷新索引，先退出游戏、恢复工具文件，再重新准备。放宽版本门禁不代表新构建全部技能和界面已经实测。

发行资源保留 7.41f / build 6944 的制作基线。资源清单校验与编译脚本的基线检查用于确认原创产物来源，与玩家启动时的客户端版本无关。

更新工具资源前必须退出游戏并恢复旧安装，禁止覆盖正在使用的安装文件。作者修改源文件后重新编译四项发行资源，并核对清单 SHA；不能以旧编译产物替代新源文件。

## 0.1.2 版本检查与新版验证

2026-10-07 在 Steam 更新后的 build 6951 / SourceRevision 11096670 完成实际准备、主菜单及普通本地比赛连接、中文目录查询、风暴之拳添加 1 级和升至 2 级，以及桌面按钮删除。20 项原技能的槽位、等级、隐藏和激活状态保持；退出后的六文件恢复及原游戏文件校验通过。实际日常窗口同时显示制作基线 7.41f / build 6944 与检测构建 6951，版本差异没有阻止操作。

106 项当前版 Node 检查全部通过，独立 Electron UI 检查覆盖其他构建和元数据缺失时的准备/启动。首次直接载图发生一次 AMD 渲染模块访问违规，主菜单入口及第二次同参数直接冷启动均正常；未确定该偶发崩溃根因。具体范围与发行指纹见 [0.1.2 验收记录](current-skill-editor-0.1.2-acceptance.md)。新构建的实际施放、原生试玩面板、游廊及跨机多人没有在本轮重复验收。
